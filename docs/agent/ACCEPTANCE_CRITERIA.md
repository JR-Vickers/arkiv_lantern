# Acceptance Criteria

Strict completion rule: If any required acceptance criterion fails, continue building. Do not weaken criteria without human approval. Future agents must not declare the project complete unless `./scripts/check.sh` passes.

| ID | Requirement | Verification Method | Relevant Test/Script | Pass/Fail Condition |
| --- | --- | --- | --- | --- |
| AC-001 | The app defines one unique project attribute and uses it on every Arkiv entity and query. | Inspect Arkiv entity/query builders and run unit/eval checks. | `./scripts/test.sh`, `./scripts/eval.sh` | Pass if all create/query paths include `project = arkiv-database-owned-memory-v1`; fail if any path can omit it. |
| AC-002 | The demo uses Arkiv Braga testnet for durable app data. | Inspect config and run smoke flow against Braga or approved Braga test harness. | `./scripts/smoke.sh`, `./scripts/eval.sh` | Pass if config targets Braga and smoke flow persists/queries data there; fail if data is stored elsewhere as source of truth. |
| AC-003 | The app implements at least two Arkiv entity types. | Inspect schemas and create/query tests. | `./scripts/test.sh`, `./scripts/eval.sh` | Pass if `memory_profile` and `memory_record` are implemented with payloads, attributes, content type, and `expiresIn`; fail if fewer than two entity types exist. |
| AC-004 | `memory_record` entities are related to `memory_profile` entities through shared attribute keys. | Inspect schema and relationship query tests. | `./scripts/test.sh` | Pass if records store and query by `profileEntityKey`; fail if relationships exist only inside unindexed payload text. |
| AC-005 | A user can connect a wallet and see ownership/account state. | Manual smoke test and automated UI smoke test where feasible. | `./scripts/smoke.sh` | Pass if wallet connection state is visible and required for writes; fail if create/update flows do not identify an owner. |
| AC-006 | A user can create and query their own memory profile. | Run profile create/query test and smoke workflow. | `./scripts/test.sh`, `./scripts/smoke.sh` | Pass if the created profile is returned after reload/query for the connected wallet; fail if it only exists in local UI state or appears because of an unscoped public query. |
| AC-007 | A user can create and query their own memory record under a profile. | Run memory create/query test and smoke workflow. | `./scripts/test.sh`, `./scripts/smoke.sh` | Pass if the created record is linked to and queryable from its profile for the connected wallet; fail if linkage is missing or owner scoping is omitted. |
| AC-008 | Users can filter/query their memory records by owner, profile, and tag. | Run query-builder and UI tests. | `./scripts/test.sh` | Pass if filters produce correct Arkiv query attributes, including `PROJECT_ATTRIBUTE`, owner scope, profile, and normalized `tag`; fail if filtering is client-only over unrelated or other-user data. |
| AC-009 | Users can inspect payload and relevant metadata for an entity. | UI test or manual smoke test. | `./scripts/smoke.sh` | Pass if detail view shows payload plus owner/creator/key or equivalent metadata; fail if metadata is hidden. |
| AC-010 | Owner-controlled update and delete are implemented. | Run owner success and unauthorized failure tests. | `./scripts/test.sh`, `./scripts/smoke.sh` | Pass if `$owner` can update/delete and non-owners cannot; fail if authorization is bypassed or untested. |
| AC-011 | Empty, loading, validation, network, and authorization error states are handled. | UI tests and smoke tests. | `./scripts/test.sh`, `./scripts/smoke.sh` | Pass if each state has a visible, non-crashing UI; fail on blank screens or swallowed errors. |
| AC-012 | User data persists through reload because Arkiv is the durable source of truth. | Create data, reload app, query again. | `./scripts/smoke.sh` | Pass if data is reloaded from Arkiv; fail if persistence depends on local storage. |
| AC-013 | README includes setup, local run, test, and deployment/demo instructions. | Inspect README and run documented commands. | `./scripts/eval.sh`, `./scripts/check.sh` | Pass if a new developer can follow README without hidden credentials; fail if setup is missing or stale. |
| AC-014 | Security rules are followed for secrets, external services, public-testnet data, and destructive actions. | Review code/config and run secret-oriented eval checks. | `./scripts/eval.sh`, review protocol | Pass if no secrets are committed, no paid/destructive actions occur without approval, and memory bodies are either encrypted or preceded by a clear public-testnet warning; fail on any secret, unsafe command, or misleading privacy behavior. |
| AC-015 | Tests cover happy paths, invalid input, boundary values, missing data, persistence, auth/security, and failure states. | Compare implementation tests to `TEST_MATRIX.md`. | `./scripts/test.sh`, `./scripts/eval.sh` | Pass if required test categories are represented; fail if critical paths are untested. |
| AC-016 | Public challenge deliverables are ready. | Inspect repo, README, demo link, and submission notes. | `./scripts/eval.sh` | Pass if repo is public/open source, demo link works, README is complete, and team/submission info is documented; fail if any required deliverable is missing. |
| AC-017 | The main acceptance gate passes. | Run the script from repo root. | `./scripts/check.sh` | Pass only if setup validation, lint, typecheck, tests, smoke checks, and evals all pass; fail if any component fails. |
